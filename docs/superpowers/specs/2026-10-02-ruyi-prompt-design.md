# RuYi 提示词节点设计规格

日期：2026-10-02  
状态：聊天中的功能与输出设计已确认；本规格等待用户审阅。

## 1. 目标与开发范围

用户希望在一个节点内维护多角色画面的提示词：快速搜索并高亮文字、通过本地词库联想输入、接入 RuYi LoRA 加载器的触发词、分段编辑，以及用红色波浪线提示拼写错误。正面与负面内容分别合并并编码，各输出一个条件，直接连接采样器。

开发和测试只在 `D:\Comfy-Desktop\ComfyUI\ComfyUI\custom_nodes\RuYi-Nodes` 进行。只有用户明确要求准备上传后，才能修改 `D:\Workshop\Github\RuYi-Nodes`。保留当前 LoRA 加载器和图像对比节点的接口、工作流及本地未提交修改。

用户最后确认的设计包含：CLIP 与触发词输入、正负编辑区、可命名/折叠/排序的段落、分别合并、两路 CONDITIONING 输出、搜索高亮、联想和拼写提示。原始消息末尾未写完整的“⑥”不作为额外功能推断。

## 2. 节点接口与编码

节点标识：`RuYiPrompt`；中文显示名：`RuYi 提示词`；英文显示名：`RuYi Prompt`；分类沿用本项目 RuYi 节点分类。

| 输入 | 类型 | 行为 |
| --- | --- | --- |
| `clip` | CLIP，必需 | 从模型的文本编码器加载节点接入；使用 LoRA 完整加载器时接其修改后的 CLIP。 |
| `prompt_data` | 自定义可序列化文本控件，必需 | 保存正负段落与编辑设置的版本化 JSON；由前端管理，提交执行时仍为字符串。 |
| `trigger_words` | STRING，可选、连线输入 | 接 RuYi LoRA 加载器的触发词输出，也允许其他字符串节点；未连接时为空。 |

仅提供两个输出，依次为 `positive` 和 `negative`，类型均为 CONDITIONING，本地化为“正面条件”和“负面条件”。本版不增加单独的文本输出端口；合并文本通过节点内的执行结果预览查看和复制。

后端分别对正负合并文本调用 `clip.tokenize(text)` 和 `clip.encode_from_tokens_scheduled(tokens)`。本机 ComfyUI 的 `CLIPTextEncode` 与已安装的 Anima 编码节点使用这一接口。保留标准编码器提供的元数据和调度行为，不自行构造或合并张量。空负面文本也正常编码；缺少有效 CLIP 时返回清楚的连线错误。

## 3. 编辑区与分段合并

默认创建一个空的正面“全局”段落和一个空的负面“负面”段落，不预填风格或质量词。正负编辑区分别显示，均可添加、重命名、折叠、上移、下移、启用/停用和删除段落。可以命名为“角色 1”“角色 2”“背景”等；每一侧至少保留一个编辑段落。

执行时，按各侧可见顺序取启用且非空的段落，去掉各段落首尾空白后以一个换行符连接。保留段落内部的标点、换行、权重括号和用户填写的提示词语法。段落名称、折叠状态、搜索词、联想候选和波浪线标记不进入最终文本。

`trigger_words` 去掉首尾空白后，作为一个独立文本块追加在正面合并文本末尾，不加入负面。每次执行重新合并，不能把触发词写回手写段落或因重复执行累计追加；不改写用户手写的重复词句。加载器自身控制各 LoRA 是否输出触发词。

“分区”在这里是编辑分组；输出仍是普通合并提示词。节点不创建空间遮罩、区域条件、角色身份绑定，也不插入 BREAK 或模型专属区域语法。

触发词预览为独立的只读区域。连线本身不能获得任意上游 STRING 的实际值；首次执行前显示“执行时获取”，执行成功后显示本次触发词和正负合并文本。改变手写段落后，旧的执行预览明确标记为上次执行结果，不能伪装成新一轮的实际输出。

## 4. 搜索与编辑器

采用原生 textarea 编辑，加一个非交互文本装饰层显示搜索高亮与拼写波浪线。装饰层使用文本节点和安全的 DOM 元素创建内容，绝不把提示词当作 HTML。textarea 与装饰层共享字体、行高、内边距、宽度、换行及滚动位置；保留光标、选区、原生撤销重做、粘贴和中文 IME 输入。

搜索默认不区分大小写、按普通文本匹配，在正面和负面的所有段落中高亮全部匹配，包括当前折叠或停用段落，并显示匹配总数。上一处/下一处按正面段落再负面段落的显示顺序导航，必要时展开目标段落并选中匹配文本。Enter 下一处，Shift+Enter 上一处，Escape 关闭搜索。空搜索词不产生高亮。搜索不修改文本，不触发编码，也不改变输出。

选择、输入与候选弹窗操作不得让 ComfyUI 画布误触发删除节点或拖拽操作。数字和输入控件继续遵循 LoRA 节点验证过的 DOMWidget 序列化契约：编辑修改实时状态，getValue 序列化；不通过写入 widget.value 触发重建。

## 5. 本地词表与联想

读取本地 CSV，并在实现时把选定词表及来源说明放到本节点的数据目录；运行时不依赖用户机器上其他工具的绝对路径。支持现有两种带表头的导出格式，以及 WebUI tag autocomplete 的无表头 `name,category,postCount,aliases` 格式；中文对照采用 `tag,translation` 格式。

已核实的本地输入文件位于 `D:\AI\Tools\3.BooruDatasetTagManager\BooruDatasetTagManagerPlus-1.2.6-win-x64\Data`：

| 文件 | 记录数 | 用途 |
| --- | ---: | --- |
| `danbooru_dataset_general.csv` | 106,414 | 通用词、别名、分类及使用频次。 |
| `danbooru_character_tags.csv` | 329,747 | 角色名称及别名。 |
| `danbooru-0-zh.csv` | 23,799 | 中文搜索及候选中文释义。 |

三个文件均已验证可按 UTF-8 解码。追加近期 Danbooru 词库以补齐画师、作品和元标签，保留本地角色表；规范词去重，合并别名和中文说明，频次取可用数据中的最大值。类别保留来源标签，避免混淆不同站点的类别编号。不同来源保持可单独启用，默认启用 Danbooru 与用户本地词表；e621 和模型专用词表为可选来源，不默默改写用户输入。

候选基于光标所在的当前标签片段，空格和下划线等价匹配，支持规范词、别名和中文释义搜索。完整匹配优先，其次前缀、子串，再按使用频次排序；最多显示 20 项。显示标签、中文释义（存在时）、类别与来源。向上/向下选择，Enter/Tab 插入，Escape 关闭；中文输入合成期间不接受候选。

插入时只替换当前片段，不覆盖其他段落或光标后的文本。普通 tags 默认把下划线转为空格；设置可保留下划线。保留模型专用词库中的 `@` 前缀。必要的字面括号按标准 ComfyUI 提示词语法转义，不改写已经存在的权重语法。

解析、索引和搜索放在共享的按需 Web Worker 中；节点未打开时不加载几十万条记录。通过本机静态文件或本机路由读取数据，不在每次按键时重复传输词表。异步结果带请求序号，过期候选不覆盖新输入。各节点共享词库索引，编辑状态互不共享。

允许导入符合上述格式的本地 CSV 和添加自定义词。来源下载在开发阶段明确执行并记录来源、获取日期、版本或 SHA256；节点运行时不自动查询、更新或下载互联网词库。

## 6. 拼写提示

首版检查英语自然语言单词。使用 wooorm/dictionaries 的英语 Hunspell `index.aff`、`index.dic` 与 Typo.js，按需在 Worker 中运行；避免依赖不同浏览器是否安装系统拼写词典。保留第三方代码及词典各自的完整许可证和来源，不安装额外 Python 包。

合法的完整 tags、别名、角色/画师名、数字/提示词语法、已解析的 LoRA 触发词和自定义词不标为拼写错误。自然语言片段按英语单词检查，支持普通大小写与词典词形变化；中文不按英语词典标红。词库未知不等同于拼写错误，不能把整段未知 tag 直接当作错误。

错误范围显示红色波浪线，可打开修正候选、忽略本次或加入节点自定义词典。点击修正只替换对应单词，不自动改写内容。自定义词随工作流保存，原始 prompt_data 中不保存波浪线范围和计算缓存。搜索高亮与波浪线可叠加。拼写检查是提示而非语法检查；不阻止节点执行。

输入检查采用约 200ms 的防抖，合成输入结束后检查，异步过期结果丢弃。字典失败时保留编辑和编码功能，明确显示拼写检查不可用，不给所有词标错。

## 7. 状态与持久化

prompt_data JSON 的版本字段为 `version: 1`，包含 positive/negative 两组段落，以及 autocomplete、拼写启用状态、下划线插入模式、启用词库和自定义词。段落包含稳定 id、title、text、enabled、collapsed。名称和 id 只用于编辑管理，不参与编码。

搜索内容、候选选择、焦点、临时滚动位置和 Worker 结果为 UI 临时状态；合并文本与触发词预览来自最近一次执行的 UI 返回，不作为新的手写输入。保存/载入工作流恢复所有编辑内容及段落顺序；复制节点后段落和设置可以独立修改。删除节点清理监听和弹窗；共享 Worker 不持有已删除节点的文本。

后端只解析执行必需的 JSON 段落字段。损坏 JSON、错误版本或非法段落结构给出具体错误，不静默输出空提示词；空段落或空负面内容是有效状态。

## 8. 文件与集成边界

新增独立的 `ruyi_prompt.py` 和 `js/ruyi_prompt.js`，分别承担合并/编码及编辑 UI。词表解析和查询逻辑、Worker 及必要的第三方拼写资源放在提示词功能目录；避免把新编辑器塞进现有 LoRA 文件。Worker 资源使用不会被 ComfyUI 当作扩展自动执行的入口格式；后台 Worker 文件不能在主线程初始化。

在 `__init__.py` 合并新节点映射；新增中英本地化；README 仅补充新节点接口、接线示例、词库来源和已验证限制。本阶段不调整发布版本、CHANGELOG、Registry、GitHub 工作副本或上传状态。

本机路由如需要，仅提供固定数据目录下的词表清单与数据。不得接受任意绝对路径读取或目录遍历参数。词表与提示词保持本地处理；不增加 ComfyUI 核心互联网请求。

## 9. 验收与测试

1. 后端验证正负分别按顺序合并、停用/空段落跳过、触发词仅正面追加、重复执行不累计、段落名不输出，以及括号/换行/中文原样保留。
2. 验证两个输出的类型和顺序；使用编码接口测试替身确认 tokenizer 接收的最终文本及条件对象无损返回；另在本机可用编码器上执行一次最小正负编码，确认能连接采样器。接口测试替身不能冒充真实模型执行结果。
3. 词表检查表头与无表头 CSV、引号内逗号、UTF-8/中文、别名/频次合并、去重及来源筛选；使用实际大词表检查首次加载和输入响应，不仅测几个样例。
4. 浏览器检查搜索总数/导航/高亮、候选键盘与鼠标选择、插入位置、光标和撤销、粘贴、中文 IME，以及滚动/缩放时装饰层对齐。
5. 拼写检查包含正确自然语言、故意拼错的单词、合法 tags/角色名/LoRA 触发词、自定义词、修正选择及异步输入过期结果。
6. 检查保存/载入、复制节点后独立编辑、添加/删除/排序/停用段落、中英文标签及节点删除清理。
7. 在实际 ComfyUI 验证与两种 RuYi LoRA 加载器接线，两路条件连接到采样器；沿用现有 LoRA 回归检查，确保此前的数量设置、箭头 hover 和滚动位置未回退。
